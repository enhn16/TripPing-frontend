# TripPing: 사용자 요구 기반 당일치기 최적화 확장형 관광 코스 추천 서비스

> 2026 관광데이터 활용 공모전

## 서비스 소개

기존 관광 추천 서비스는 동행자 구성, 여행 목적 등 사용자의 다양한 여행 상황을 충분히 반영하지 못하는 한계가 있습니다. 예를 들어 대학생과 초등학생 동생이 함께 나들이를 계획할 때 '아이 동반' 조건으로 검색하면 키즈카페나 박물관 같은 획일적인 장소만 추천되는 식입니다.

본 서비스는 자연어 입력과 선택형 조건을 결합해 사용자 요구를 정밀하게 분석하고, 핵심 관광지를 중심으로 주변 코스를 단계적으로 확장하는 **거점 기반 확장형 추천 구조**를 통해 당일치기 여행에 최적화된 맞춤형 코스를 제공합니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 조건/자연어 기반 관광지 추천 | 여행 타입(자연/도시/복합), 연령, 동행자(연인/아이/가족), 지역 등 선택 조건 + 자유 텍스트 입력 |
| 주요 관광지 선택 및 확장 추천 | 주요 관광지 3곳 추천 → 사용자가 선택한 곳을 중심으로 주변 명소·식당·카페 확장 추천 |
| 코스 카드 생성 및 공유 | 확정 경로를 카드 형태로 시각화, 저장 및 SNS 공유 지원 |
| 코스 카드 보관함 | 생성된 코스 카드를 한눈에 모아보는 보관함 제공 |

**서비스 흐름**: 여행 조건 입력 → 추천 관광지 선택 → 코스 카드 생성


## 차별성

- 필터 기반 나열식 추천이 아닌, 자연어+조건 결합으로 사용자 의도를 정교하게 반영
- 추천 결과를 단순 수용하는 대신 사용자가 직접 관광지를 선택하고 코스를 확장해 나가는 능동적 참여 구조
- 효율적 동선의 당일치기 코스 + 직관적인 카드형 시각화 및 공유

## 웹사이트 실행 및 배포

이 프로젝트는 React + Vite 웹사이트입니다. Node.js 22.12 이상에서 실행하세요.

```sh
npm ci
# .env가 없을 때만 .env.example을 .env로 복사하고 값을 설정합니다.
npm run dev -- --host 127.0.0.1
```

브라우저에서 http://127.0.0.1:5173 에 접속합니다. 기존 `.env`는 그대로 사용합니다.
`npm run lint`로 검사하고 `npm run build`로 정적 사이트를 `dist/`에 생성합니다.
`npm run preview`로 빌드 결과를 로컬에서 확인할 수 있습니다.

- PC에서는 여행 유형을 3열로, 관광지 선택 화면을 지도/목록 2열로 보여줍니다. 모바일에서는 세로 배치를 사용합니다.
- 시작 화면은 자동으로 사라지지 않는 웹 홈입니다. 기존 추천 API와 회원 보관함을 사용합니다.
- 이미지는 브라우저에서 PNG로 다운로드합니다. 파일 공유를 지원하는 HTTPS 브라우저에서는 공유창을 열고, 미지원 또는 공유 권한 오류 시 다운로드합니다. 사용자가 공유를 취소하면 다운로드하지 않습니다.
- 기존 카드 캡처 정책대로 장소 썸네일은 저장 이미지에서 제외됩니다. 지도 이미지 서버는 캡처를 위해 CORS를 허용해야 합니다.
- `android/`, `capacitor.config.json`, 앱 아이콘 원본은 이전 앱 자료로 보존되어 있으며 웹 실행/빌드에는 사용되지 않습니다. 네이티브 의존성은 제거했습니다.

### 운영 환경 연결

1. `VITE_API_BASE_URL`을 실제 HTTPS 백엔드 주소로 설정하고 다시 빌드합니다. API 서버는 별도로 실행되어야 합니다. `/api`를 동일 출처에서 프록시할 때만 이 값을 비워둡니다.
2. 백엔드 CORS 허용 출처에 웹사이트 주소를 추가합니다. HTTPS 웹에서 HTTP API 호출은 사용할 수 없습니다.
3. 카카오 개발자 콘솔에 실제 웹사이트 도메인과 로그인 Redirect URI `https://웹사이트주소/select`를 등록합니다. 지도용 JavaScript 키도 해당 웹 도메인에서 허용되어야 합니다. 백엔드 인가 코드 교환의 redirect URI도 같은 주소를 사용해야 합니다.
4. `VITE_` 변수는 브라우저에 공개됩니다. Client Secret과 서버 비밀키는 백엔드에서만 관리합니다. `VITE_DEV_FORCE_LOGIN`은 개발 모드에서만 적용됩니다.
5. 배포 디렉터리는 `dist`입니다. `/select`, `/storage/123` 같은 주소에 직접 접속하거나 새로고침할 때 `index.html`을 반환하도록 SPA rewrite가 필요합니다. Netlify용 `public/_redirects`, Vercel용 `vercel.json`을 포함했습니다. 이 설정은 외부 API 주소를 사용하는 구성이며 같은 출처의 `/api`를 사용하려면 호스팅에서 API 프록시를 별도로 구성해야 합니다.

추천 중간 화면은 이전 단계의 선택 데이터가 필요합니다. 추천은 홈의 ‘로그인 없이 사용하기’ 또는 카카오 로그인 후 시작하고, 저장된 코스는 `/storage/:savedCourseId`로 조회합니다. 오프라인 추천은 지원하지 않습니다.


### 전체 화면 웹 레이아웃

- 시작페이지에서 비회원 시작과 카카오 로그인을 제공합니다. 별도 로그인 화면은 제거했고 이전 `/login` 주소는 홈으로 연결합니다.
- 1920×1080을 포함한 데스크톱에서 페이지 폭 제한 없이 배경을 화면 전체에 채웁니다.
- 요구사항 화면은 좌측에 나이·동행자·지역, 우측에 추가 요구사항 입력을 배치합니다.
- 관광지 및 세부 관광지 선택 화면은 상단 메뉴 아래 전체 높이를 지도 60% / 목록 40%로 나눕니다. 목록은 독립적으로 스크롤합니다.
- 카드의 이미지 저장·공유 버튼은 카드 바로 위에서 카드와 같은 너비로 표시합니다. 뒤로가기 위치는 유지합니다.

- 홈 이동은 상단 TripPing 로고로 통일했습니다. 별도 홈 버튼과 여행 만들기 메뉴는 제거했습니다.
- 모든 페이지의 상단 보관함 버튼은 비회원에게 동일한 로그인 안내 팝업을 표시합니다.
- 카카오 로그인 버튼과 팝업은 기존 말풍선 아이콘을 공유합니다.
- 데스크톱 요구사항 화면의 동행자 6개는 한 줄로 표시하며, 지역은 스크롤 가능한 목록에서 선택합니다.
- 추천 관광지 목록은 3개 카드가 가용 높이를 균등하게 나눠 쓰고, 큰 사진과 설명을 표시합니다.
